# BIP39 离线钱包恢复工具

[English README](README.md)

本项目提供两个以离线使用为目标的 Python 工具，用于在已经掌握绝大部分 BIP39 助记词信息时恢复 Bitcoin 钱包。仅限恢复你本人拥有或已经获得明确授权的钱包。


## 相关标准与依赖项目

- [Bitcoin BIP39 规范与词表](https://github.com/bitcoin/bips/tree/master/bip-0039)：Bitcoin Improvement Proposal 中与 BIP39 助记词有关的资料，包含助记词构造、checksum 规则、种子生成方法以及官方语言词表。
- [bip_utils](https://github.com/ebellocchia/bip_utils)：本项目使用的 Python 库，负责标准 BIP39 种子生成，以及 BIP44、BIP49、BIP84、BIP86 的密钥和地址派生。

## 选择正确的恢复工具

### `01_bip39_order_recovery.py`

适用于：全部助记词单词都正确，但是顺序被打乱。

支持 12、18、24 个英文 BIP39 单词，支持空格或逗号输入，也支持可选的 BIP39 passphrase。程序仅扫描 Bitcoin 主网，并检查 BIP44、BIP49、BIP84、BIP86，在 account 0 下扫描外部地址索引 0、1，以及内部/找零地址索引 0、1，总计 16 条路径。

完整排列的数量增长非常快。12 个互不重复的词有 `12! = 479,001,600` 种顺序；18 词和 24 词完全乱序通常无法在现实时间内穷举，虽然程序仍会按照设定逻辑执行。

### `02_bip39_wrong_words_recovery.py`

适用于：助记词顺序正确，但是可能有 0、1 或 2 个词错误。

支持 12 或 24 个英文 BIP39 单词。如果输入的词不在 BIP39 词表中，程序会把对应位置视为强错误位置提示；如果所有输入词都属于 BIP39 词表，程序还必须遍历可能的错误位置。目标地址前缀用于选择 BIP44、BIP49、BIP84 或 BIP86，然后扫描该标准下同样的 4 个 account-0 地址位置。

两个词错误的搜索量仍可能非常大，尤其是两个错误词本身也都是合法 BIP39 单词，而且错误位置都未知时。

## BIP39 checksum 的准确说明

BIP39 助记词不是从词表中任意挑选的单词序列。它编码了随机熵和 checksum。checksum 取自该熵 SHA-256 哈希的前若干位，关系为 `CS = ENT / 32`；助记词承载的总位数是 `ENT + CS`，再按每 11 位映射到一个词表索引。

| 助记词数量 | 熵 | Checksum | 随机候选平均通过率 |
|---:|---:|---:|---:|
| 12 | 128 位 | 4 位 | 约 1/16 |
| 18 | 192 位 | 6 位 | 约 1/64 |
| 24 | 256 位 | 8 位 | 约 1/256 |

两个程序都会在 PBKDF2 种子生成、BIP32 派生和地址编码之前执行 checksum。checksum 不通过的候选会立即跳过，地址对比次数为 0。这样可以显著减少真正进行地址派生的候选数量。

checksum 通过只表示候选在 BIP39 结构上有效，并不能证明它就是你的钱包，也不能证明所有权。最终必须由派生地址与用户提供的已知 Bitcoin 地址完全一致来确认。

### 可复现的实际 checksum 测试数量

以下数字来自项目内嵌的 2048 词表和脚本中的 checksum 实现，使用公开测试数据，可重复验证：

1. 顺序恢复测试：使用 11 个 `abandon` 和 1 个 `about`。由于有 11 个重复词，唯一排列总数正好是 12。其中 checksum 有效 1 个，直接跳过 11 个；完整 checksum 扫描时只有 1 个候选会进入地址派生。
2. 错词恢复测试：前 11 个词为 `abandon`，最后一个词为不在词表中的错误词。将最后一位遍历全部 2,048 个 BIP39 单词时，checksum 有效 128 个，直接跳过 1,920 个。若没有 checksum 过滤，2,048 个候选都需要进行种子和地址计算。
3. 按词表索引顺序扫描时，正确的最后一个词 `about` 的索引是 3。遇到公开地址匹配后停止的测试共检查 4 个替换词，其中 checksum 有效 1 个，跳过 3 个，真正进入地址派生的只有正确候选。

这些精确数字只针对上述公开测试数据。其他受约束的候选集合中，实际有效数量可能与统计期望略有差异，但上表中的概率仍是一般情况下正确的估计。

## 安装与运行

需要 Python 3.10 或更高版本。安装固定版本依赖：

```text
python -m pip install -r requirements.txt
```

更安全的操作流程是：准备可信且干净的电脑，安装 Python 和依赖，断开网络，然后运行脚本：

```text
python 01_bip39_order_recovery.py
python 02_bip39_wrong_words_recovery.py
```

中文版本：

```text
python zh/01_bip39_order_recovery_zh.py
python zh/02_bip39_wrong_words_recovery_zh.py
```

程序启动后通过交互式输入读取数据，不把助记词作为命令行参数。为了便于检查输入错误，助记词和 passphrase 会显示在终端屏幕上。

## 务必保护好助记词

完整助记词与正确 passphrase（如果钱包使用了 passphrase）基本等同于钱包最高控制权。不要把真实助记词发给任何人，不要粘贴到网站、在线表单、聊天软件、云笔记、远程协助窗口或不可信的所谓“恢复服务”。不要截图、录屏、直播或让旁人看到恢复过程。

优先使用可信、干净、断网的电脑。检查远程控制软件、剪贴板同步、云备份、键盘记录器、恶意输入法、终端日志和虚拟机宿主机暴露。脚本本身不会主动把助记词、恢复结果、进度断点或日志写入磁盘，但操作系统和其他软件仍可能记录键盘或屏幕内容。

恢复成功后，应把旧助记词视为已经在通用电脑上暴露。建议使用可信硬件钱包或离线设备生成全新钱包，先进行小额验证，再尽快把其余资产转移到新钱包。

正式输入真实钱包信息前，建议先使用以下公开测试助记词检查环境：

```text

```

Passphrase 留空。BIP84 路径 `m/84'/0'/0'/0/0` 的公开地址为：

```text
bc1qcr8te4kr609gcawutmrza0j4xv80jy8z306fyu
```

测试顺序恢复时，可以把 `about` 移到最前面。由于该助记词包含 11 个重复的 `abandon`，唯一排列只有 12 个，适合快速功能检查，不适合作为普通 12 词乱序的速度基准。

测试错误词恢复时，可以把最后一个 `about` 改为不在 BIP39 词表中的 `xxxxx`，继续使用同一个公开地址。程序应定位第 12 个词，并恢复为 `about`。
