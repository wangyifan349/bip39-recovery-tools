# BIP39 Recovery Tools

[English](README.md) | **简体中文**

[GitHub 项目主页](https://github.com/wangyifan349/bip39-recovery-tools) · [Issues](https://github.com/wangyifan349/bip39-recovery-tools/issues) · [`bip-utils` 源码](https://github.com/ebellocchia/bip_utils) · [`bip-utils` PyPI](https://pypi.org/project/bip-utils/)

用于在**已知比特币主网地址**的辅助下，离线恢复两类 BIP39 英文助记词问题：

1. 助记词单词全部正确，但顺序被打乱；
2. 助记词顺序正确，但有 0–2 个单词错误。

本项目提供英文与中文交互脚本。脚本会先执行 BIP39 校验和过滤，再从候选助记词派生比特币地址，并与用户提供的已知地址精确比较。

> [!CAUTION]
> **只可恢复你本人拥有或已获明确授权的钱包。** 助记词与 BIP39 passphrase 可完全控制钱包资产。请在可信、断网、无远程控制、无云剪贴板同步的设备上运行；不要把真实助记词提交到网站、聊天工具、在线代码运行器或任何第三方服务。

> [!IMPORTANT]
> 本工具不是“仅凭一个地址找回助记词”的工具。你必须已经掌握完整数量的助记词单词，并且问题属于本项目覆盖的范围。已知地址只用于从候选结果中确认正确答案。

## 如何选择脚本

### 情况 A：所有单词都正确，只是顺序不确定

运行：

```bash
python zh/01_bip39_order_recovery_zh.py
```

适用条件：

- 单词数量为 12、18 或 24；
- 每个单词都属于官方 BIP39 英文词表；
- 只需要重新排列现有单词；
- 已知同一个钱包的一个受支持地址；
- 若原钱包使用了 BIP39 passphrase，必须准确知道它。

### 情况 B：顺序正确，但最多两个位置的单词错误

运行：

```bash
python zh/02_bip39_wrong_words_recovery_zh.py
```

适用条件：

- 单词数量为 12 或 24；
- 单词位置顺序没有被打乱；
- 最多两个位置需要替换；
- 错误单词可能不在 BIP39 词表，也可能恰好是另一个合法 BIP39 单词；
- 已知同一个钱包的一个受支持地址；
- 若原钱包使用了 BIP39 passphrase，必须准确知道它。

### 不要混用两种脚本

错词脚本**不会重新排列单词**；顺序脚本**不会替换单词**。如果助记词同时存在顺序错误和错词，本项目当前代码不覆盖该组合场景。

## 已知地址、收款地址与找零地址

### “已知地址”到底是什么

已知地址必须满足以下条件：

- 来自你要恢复的同一个钱包；
- 是比特币**主网**地址；
- 地址类型与本项目支持的标准派生路径一致；
- 位于账户 `0`；
- 位于外部收款链或内部找零链；
- 地址索引为 `0` 或 `1`；
- 能与程序派生出的地址逐字符匹配。

它可以是下列任意一个：

| 地址用途 | 链 | 索引 | 示例路径后缀 |
|---|---:|---:|---|
| 第 1 个收款地址 | `0` | `0` | `/0/0` |
| 第 2 个收款地址 | `0` | `1` | `/0/1` |
| 第 1 个找零地址 | `1` | `0` | `/1/0` |
| 第 2 个找零地址 | `1` | `1` | `/1/1` |

因此，已知地址**不一定是钱包界面显示的第一个收款地址**。只要它确实属于候选钱包，并且落在上述扫描范围内，找零地址也可以用于确认恢复结果。

### 不能使用什么地址

以下地址不会帮助程序匹配：

- 交易对手、交易所充值方或其他第三方的钱包地址；
- 仅仅出现在交易记录中、但并非由你的钱包派生的地址；
- 账户 `1` 或更高账户的地址；
- 索引 `2` 或更高的收款/找零地址；
- 自定义路径、厂商专用路径或非标准账户结构下的地址；
- 测试网地址；
- 多签、描述符钱包或并非本项目支持的单签标准所产生的地址。

> [!NOTE]
> “找零地址”是钱包内部链生成的地址，通常用于接收交易找回的零钱。它仍然是你钱包控制的地址，并不是“余额找零”或“根据余额反查地址”的功能。

### 地址前缀与标准

| 地址前缀 | 地址类型 | 标准 | 用途路径前缀 |
|---|---|---|---|
| `1...` | Legacy P2PKH | BIP44 | `m/44'/0'/0'` |
| `3...` | Nested SegWit P2SH-P2WPKH | BIP49 | `m/49'/0'/0'` |
| `bc1q...` | Native SegWit P2WPKH | BIP84 | `m/84'/0'/0'` |
| `bc1p...` | Taproot P2TR | BIP86 | `m/86'/0'/0'` |

顺序恢复脚本会对每个通过校验和的候选同时扫描 BIP44、BIP49、BIP84 和 BIP86。

错词恢复脚本会根据地址前缀选择一种标准：

- `1...` → BIP44；
- `3...` → BIP49；
- `bc1q...` → BIP84；
- `bc1p...` → BIP86。

注意：并非所有 `3...` 地址都是 BIP49 单签地址。多签或其他 P2SH 地址虽然同样以 `3` 开头，但不一定能由本工具匹配。

## 实际扫描的派生路径

程序固定使用 Bitcoin 主网币种索引 `0'`、账户 `0'`，并检查外部链与内部链的前两个地址。

| 标准 | 第 1 个收款 | 第 2 个收款 | 第 1 个找零 | 第 2 个找零 |
|---|---|---|---|---|
| BIP44 | `m/44'/0'/0'/0/0` | `m/44'/0'/0'/0/1` | `m/44'/0'/0'/1/0` | `m/44'/0'/0'/1/1` |
| BIP49 | `m/49'/0'/0'/0/0` | `m/49'/0'/0'/0/1` | `m/49'/0'/0'/1/0` | `m/49'/0'/0'/1/1` |
| BIP84 | `m/84'/0'/0'/0/0` | `m/84'/0'/0'/0/1` | `m/84'/0'/0'/1/0` | `m/84'/0'/0'/1/1` |
| BIP86 | `m/86'/0'/0'/0/0` | `m/86'/0'/0'/0/1` | `m/86'/0'/0'/1/0` | `m/86'/0'/0'/1/1` |

顺序恢复脚本对每个通过 BIP39 校验和的候选最多比较 16 个地址：4 种标准 × 4 个位置。

错词恢复脚本先由地址前缀确定标准，再比较该标准的 4 个位置。

## 恢复算法

### 1. 顺序恢复

程序执行以下步骤：

1. 接收 12、18 或 24 个英文单词；
2. 执行 Unicode NFKD 规范化并转换为小写；
3. 检查每个单词是否属于内置的 2048 词 BIP39 英文词表；
4. 生成这些单词的唯一排列；
5. 对每个排列先验证 BIP39 校验和；
6. 只有校验和有效的候选才生成 BIP39 seed；
7. 使用用户输入的 passphrase 派生地址；
8. 扫描 BIP44、49、84、86 的 16 个受支持位置；
9. 找到与已知地址完全匹配的结果后立即停止。

如果输入中有重复单词，程序只生成唯一排列，搜索总数会相应减少。

### 2. 错词恢复

程序执行以下步骤：

1. 接收 12 或 24 个、顺序已经正确的英文单词；
2. 找出不在 BIP39 词表中的位置；
3. 若非法词超过两个，立即拒绝；
4. 若有一个或两个非法词，将这些位置作为已知错误位置；
5. 若所有单词都在词表中，则错误位置未知，程序会枚举所有可能位置；
6. 按 0 个替换、1 个替换、2 个替换的顺序测试候选；
7. 对每个候选先验证 BIP39 校验和；
8. 只有有效候选才派生地址；
9. 根据已知地址前缀选择 BIP44、49、84 或 86；
10. 比较收款链和找零链的索引 0、1；
11. 找到精确地址匹配后输出被替换的位置、原词、新词和派生路径。

当一个原词本身已经是合法 BIP39 单词时，替换时会排除原词，因此该位置有 2047 种替代词；非法词位置有 2048 种可能。

### BIP39 校验和过滤

BIP39 助记词不是任意词表单词组合。助记词末尾包含由熵计算出的校验位：

```text
CS = ENT / 32
```

校验和过滤能在昂贵的 seed 和地址派生之前排除大部分候选。理论上，随机候选通过校验和的比例大约为：

| 单词数 | 校验位 | 通过概率 |
|---:|---:|---:|
| 12 | 4 | 1 / 16 |
| 18 | 6 | 1 / 64 |
| 24 | 8 | 1 / 256 |

校验和有效**不代表候选就是你的钱包**；最终仍以已知地址匹配为准。

## 搜索空间与性能

### 顺序恢复的排列数量

若所有单词互不重复：

| 单词数 | 排列数量 |
|---:|---:|
| 12 | `12! = 479,001,600` |
| 18 | `18! = 6,402,373,705,728,000` |
| 24 | `24! = 620,448,401,733,239,439,360,000` |

18 和 24 个完全打乱且互不重复的单词通常远超单机穷举的现实范围。重复单词会降低唯一排列数量，但仍应先评估搜索规模。

### 错词恢复的候选数量

候选数量取决于非法词是否直接暴露了错误位置。

| 输入情况 | 12 词 | 24 词 |
|---|---:|---:|
| 两个非法词，两个错误位置已确定 | `2048² = 4,194,304` | `2048² = 4,194,304` |
| 一个非法词，另一个错误位置未知 | `46,116,864` | `96,423,936` |
| 所有词都合法，0–2 个错误位置未知 | `276,578,359` | `1,156,546,813` |

以上是候选上限；程序找到第一个精确匹配后会提前结束。运行速度取决于 CPU、Python 版本、候选通过校验和的比例及地址派生成本。

### 当前性能特性

- 单进程、单线程；
- 不使用 GPU；
- 不支持分布式搜索；
- 不保存检查点；
- 中断后不能从断点恢复；
- 运行时间可能很长，尤其是 18/24 词排列或错误位置未知时。

🧪 在输入真实秘密之前，建议先用下方公开测试向量确认环境和速度。

## 环境要求

- Python 3.10 或更高版本；
- Python 自带的 `pip` 包管理器；
- 项目直接依赖：[`bip-utils==2.12.1`](https://pypi.org/project/bip-utils/)；
- 足够的 CPU 时间；
- 推荐使用可信的离线计算机；
- 不需要区块链节点、RPC、区块浏览器、余额 API 或联网查询。

`requirements.txt` 当前只声明一个直接依赖：

```text
bip-utils==2.12.1
```

[`bip-utils`](https://github.com/ebellocchia/bip_utils) 用于根据候选助记词和 BIP39 passphrase 生成 seed，并完成 BIP44、BIP49、BIP84、BIP86 的密钥与 Bitcoin 地址派生。它所需的间接依赖会由 `pip` 自动安装。PyPI 发行包名称是 **`bip-utils`**，Python 导入模块名称是 **`bip_utils`**；不要误装名称不同的 `bip` 或拼写错误的 `bip-untils`。

本项目不是 Web 服务，也没有服务器端组件。这里的“部署”是指使用本机已有的 Python 直接安装依赖并运行脚本，不需要创建虚拟环境。不要把它部署成公开网站，也不要通过网页表单收集助记词。

## 本地离线部署

### 推荐流程

1. 在一台联网但可信的机器上下载项目和 Python 依赖；
2. 校验项目来源；
3. 使用干净介质转移到专用离线设备；
4. 在离线设备上使用系统 Python 安装本地依赖；
5. 断开网络、远程桌面、云剪贴板和同步软件；
6. 先运行公开测试；
7. 再输入真实助记词；
8. 恢复后将资产迁移到全新钱包。

### 输入格式

助记词可用空格、英文逗号或中文逗号分隔。程序会执行 NFKD 规范化并转换为小写。

```text
word1 word2 word3 ...
```

或：

```text
word1, word2, word3, ...
```

错词恢复脚本要求每个输入项为英文字母。可使用一个明显不在词表中的占位词（例如公开测试中的 `xxxxx`）来明确错误位置，但不要在真实恢复中随意增加或删除单词。

### BIP39 passphrase

- 没有使用 passphrase：直接留空并按 Enter；
- 使用了 passphrase：必须逐字符准确输入；
- 大小写、空格、标点和 Unicode 形式都会影响结果；
- passphrase 不是钱包应用 PIN、设备解锁码或交易密码；
- 当前脚本使用普通终端输入，passphrase 会显示在屏幕上。

> [!WARNING]
> 输入错误的 passphrase 仍可能生成格式正确但完全不同的钱包。程序不会“猜测” passphrase，也无法判断你是否漏填。

## 输出与结果解释

运行期间会显示或统计：

- 候选总数；
- 已检查数量；
- 剩余数量与百分比；
- 通过 BIP39 校验和的候选数；
- 地址比较次数；
- 当前处理速度；
- 估算剩余时间。

匹配成功时，程序会输出：

- 完整恢复后的助记词；
- 使用的 BIP39 passphrase 状态；
- 地址标准；
- 完整派生路径；
- 地址位置（收款或找零，索引 0 或 1）；
- 匹配地址；
- 对错词恢复，还会列出被替换的位置、原词和新词。

程序在发现第一个精确匹配后停止。请在离线环境中独立验证助记词、passphrase 和派生路径，再进行任何资金操作。

## 失败排查

| 现象 | 常见原因 | 处理方法 |
|---|---|---|
| 输入后立即报单词无效 | 单词拼写错误，或并非英文 BIP39 | 对照 BIP39 英文词表；若是错词问题，改用错词脚本 |
| 错词脚本提示非法词超过两个 | 至少三个输入项不在词表 | 本项目只覆盖最多两个错词 |
| 地址格式不支持 | 测试网、其他币种、非支持前缀或输入有误 | 使用 Bitcoin 主网 `1`、`3`、`bc1q` 或 `bc1p` 地址 |
| 找不到结果，但助记词看似正确 | passphrase 错误或漏填 | 核对大小写、空格、标点及是否真的使用过 passphrase |
| 找不到结果，地址确定属于钱包 | 地址索引、账户或路径超出扫描范围 | 确认是否为账户 0、外部/内部链索引 0 或 1 |
| `3...` 地址找不到 | 地址可能不是 BIP49 单签 P2SH-P2WPKH | 核对钱包地址类型和实际派生路径 |
| 搜索极慢 | 搜索空间过大 | 先确认问题类型、错误位置、地址路径和输入准确性 |
| 中断后无法续跑 | 当前代码无检查点 | 重新运行；长任务前先评估搜索规模 |
| `ModuleNotFoundError: bip_utils` | `bip-utils` 未安装到运行脚本所用的 Python | Windows 执行 `py -3 -m pip install -r requirements.txt`；macOS/Linux 执行 `python3 -m pip install -r requirements.txt` |
| 安装后仍提示缺少依赖 | 安装依赖和运行脚本使用了不同解释器 | Windows 统一使用 `py -3`；macOS/Linux 统一使用 `python3`，并通过 `-m pip` 安装 |

### 结果始终找不到时逐项确认

1. 助记词数量是否正确；
2. 选择的脚本是否与问题类型一致；
3. 单词是否来自英文 BIP39 词表；
4. 单词顺序是否确实固定或确实全部打乱；
5. 错词是否不超过两个；
6. passphrase 是否完全准确；
7. 地址是否由同一钱包生成，而不是第三方地址；
8. 地址是否是 Bitcoin 主网地址；
9. 地址是否属于 BIP44、49、84 或 86；
10. 地址是否位于账户 0；
11. 地址是否是 `/0/0`、`/0/1`、`/1/0` 或 `/1/1`；
12. 原钱包是否使用了非标准路径、多签、描述符或厂商自定义派生。

### 运行中

- 不要直播、截图或录屏；

### 恢复后

恢复过程意味着助记词曾在通用计算机上暴露。即使脚本本身不主动写入助记词，操作系统、终端、输入法、虚拟机宿主、剪贴板或恶意软件仍可能记录内容。

建议：

1. 在可信硬件钱包或专用离线设备上创建全新钱包；
2. 安全备份新助记词；
3. 先发送小额测试；
4. 确认后迁移全部资产；
5. 不再继续使用已暴露的旧助记词；
6. 清理临时介质，但不要依赖“删除文件”代替资产迁移。

## 明确限制

当前代码只覆盖以下范围：

- BIP39 **英文**词表；
- 12、18、24 词顺序恢复；
- 12、24 词的 0–2 个错词恢复；
- Bitcoin 主网；
- BIP44、BIP49、BIP84、BIP86；
- 账户 `0`；
- 外部收款链 `0` 与内部找零链 `1`；
- 每条链的索引 `0` 和 `1`；
- 单签标准地址；
- 精确已知地址匹配。

当前代码不支持：

- 测试网；
- 其他加密货币；
- 非英文 BIP39 词表；
- Electrum seed、SLIP39、Shamir 分片或其他助记词格式；
- 三个或更多错词；
- 同时存在乱序与错词；
- 缺失单词或多余单词；
- 猜测未知 passphrase；
- 账户发现或 gap-limit 扫描；
- 地址索引 `2` 及以上；
- 自定义派生路径；
- 多签、描述符钱包、脚本策略恢复；
- 从区块链查询余额、历史或“有钱地址”；
- 仅凭地址逆推出私钥、seed 或助记词；
- 并行、GPU、分布式或断点续跑。

## 常见问题

### 可以用找零地址吗？

可以，但必须是同一钱包在账户 0 下、受支持标准的内部链索引 0 或 1，即路径后缀 `/1/0` 或 `/1/1`。

### 可以用第二个收款地址吗？

可以。程序检查 `/0/0` 和 `/0/1`。

### 可以输入任意交易记录里的地址吗？

不可以。地址必须由待恢复钱包本身派生。交易对手地址、交易所地址和其他第三方地址不会匹配。

### 可以通过余额找到地址吗？

不可以。本项目不连接区块链，不查询余额或交易历史，只做本地密码学派生与精确地址比较。

### 地址索引 5 或账户 2 可以吗？

不可以。当前代码固定到账户 0，并只检查每条链的索引 0、1。

### 忘记了 passphrase 可以一起找吗？

不可以。passphrase 必须准确提供；空 passphrase 与任何非空 passphrase 都会生成不同钱包。

### 为什么合法 BIP39 组合仍然不是我的钱包？

BIP39 校验和只证明组合格式有效。大量不同助记词都能通过校验和，必须继续派生并匹配已知地址。

### 程序会联网吗？

恢复逻辑不需要网络或区块链服务。首次通过 PyPI 安装 `bip-utils` 及其间接依赖通常需要联网；也可以先下载到 `wheels/`，再转移到断网设备安装和运行。

### 程序会保存助记词吗？

脚本本身不设计结果文件、日志或检查点，并设置为不生成 Python 字节码缓存。但这不能保证操作系统、终端、输入法、宿主机或其他软件没有记录输入。

### 找到结果后可以继续使用原钱包吗？

技术上可能可以，但不建议。助记词已在通用计算机上暴露，应尽快迁移到新钱包。
